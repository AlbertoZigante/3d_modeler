Panel Attachment Strategies

A technical reference for describing, classifying and detecting the ways panels or geometric elements attach to one another. The document is designed to provide a common vocabulary for implementation of detectJoints().

Geometry Topology Joint detection Implementation guide

1. Introduction

A panel attachment is a geometric relationship between two or more elements where their boundaries, centerlines or surfaces establish a meaningful connection.

Core principle

The detection system should separate geometry from topology: first determine where elements interact, then determine how they interact.

2. Goals & principles

Robustness

Do not depend on exact floating-point equality. All spatial and angular decisions should use configurable tolerances.

Extensibility

Adding a new joint type should not require rewriting the intersection engine.

Topology first

A physical three-way joint should be represented as one joint even if several pairwise intersections generated it.

Explainability

Each detected joint should retain enough information to explain why it was classified that way.

4.1 Endpoint attachment

High priority2 elements

Two elements meet at one or both endpoints.

Detection rule

The intersection is within endpointTolerance of an endpoint of the participating element(s).

Important distinction

If both elements have the same direction, classify it as collinear. If their directions differ substantially, classify it as a corner/L-joint.

4.2 T-junction

High priority2 elements

One element terminates against the interior of another element.

──────────────────
         │
         │
         │

Detection rule

  • The intersection lies near an endpoint of element A.
  • The intersection lies in the interior of element B.
  • The two elements are not considered coincident.

Topology

The supporting element has continuity through the joint, while the attached element terminates at it.

4.3 Corner / L-joint

High priority2 elements

Two elements meet at their endpoints and form a non-collinear angle.

────────●
        │
        │

Detection rule

Both elements terminate at the joint and the angle between their directions is outside the collinear tolerance.

The exact angle does not have to be 90°. A 45° or arbitrary-angle corner should still be represented as a corner if the application does not require finer semantic classification.

4.4 Collinear joint

High priority2 elements

Two elements meet end-to-end and lie on approximately the same supporting line.

──────────●──────────

Detection rule

Endpoint proximity is satisfied and the absolute angle between the supporting directions is approximately 0° (or 180°, depending on orientation convention).

Why keep this type? It prevents a continuous chain of separately modeled panels from being mistaken for a corner.

4.5 Crossing / X-joint

High priority2 elements

Two elements intersect in their interiors, without either one terminating at the intersection.

Detection rule

The intersection is interior to both finite elements and is not within endpoint tolerance of either one.

Optional refinement

Store the crossing angle. This allows downstream consumers to distinguish perpendicular crossings from shallow-angle crossings.

4.6 Y-junction

Medium priority3 elements

Three elements converge at a common physical joint.

Detection rule

Generate pairwise intersections first, then spatially cluster nearby candidates. If three distinct elements participate in the same cluster, classify the cluster as a Y-junction when their endpoint/interior relationships match the intended topology.

4.8 Overlap / coincident attachment

Medium priorityspecial case

Two elements occupy the same or substantially overlapping geometry.

Element A: ─────────────────
Element B: ─────────────────
Do not treat this as a normal point intersection. Coincident geometry produces an interval of intersection rather than a single point.

This should normally be detected by a separate overlap test before point-intersection classification.

4.9 Curve attachment

Laterline/curve or curve/curve

One or both participating elements are curved.

Examples include line-to-arc, arc-to-arc and spline intersections. The same topological concepts apply, but direction should be derived from the local tangent rather than a single endpoint vector.

5.1 Candidate generation

For large models, avoid testing every possible pair. Use a spatial index, bounding boxes or another broad-phase mechanism to eliminate pairs that cannot intersect.

5.2 Narrow-phase intersection

Perform the precise line-line, line-curve or curve-curve calculation only for candidate pairs.

6. Tolerances

Geometric detection should never depend on exact floating-point equality.

TolerancePurposeExample
positionToleranceDetermines whether two locations represent the same physical point.Merge (100.01, 50.00) and (100.00, 50.01).
endpointToleranceDetermines whether an intersection counts as an endpoint.Intersection 0.02 units from endpoint.
angleToleranceDetermines whether directions are considered parallel/collinear.1° deviation may still be considered collinear.
overlapToleranceDetermines whether near-coincident geometry is considered overlapping.Useful for imported/noisy geometry.
Tolerances should ideally be configurable and, where appropriate, expressed relative to model scale rather than hard-coded globally.

7. Classification

A useful classification sequence is:

  1. Is the intersection empty? → no joint.
  2. Is the intersection an interval? → overlap/coincident case.
  3. Are there endpoint matches? → endpoint/T/L/collinear candidate.
  4. Is the intersection interior to both elements? → crossing candidate.
  5. Are curves involved? → use local tangents.
  6. After clustering, how many unique elements participate? → Y or multi-way classification.

11. Pseudocode

function detectJoints(elements):
    candidates = []

    normalized = normalize(elements)

    pairs = findCandidatePairs(normalized)

    for (a, b) in pairs:
        result = intersect(a, b)

        if result.isOverlap:
            candidates.add(makeOverlapJoint(a, b, result))
            continue

        if not result.hasPoint:
            continue

        p = result.point

        aEnd = isNearEndpoint(a, p)
        bEnd = isNearEndpoint(b, p)

        angle = angleAt(a, b, p)

        type = classifyPair(aEnd, bEnd, angle)

        candidates.add(
            makeCandidate(p, type, [a.id, b.id])
        )

    clusters = clusterByPosition(candidates)

    joints = []

    for cluster in clusters:
        joint = mergeCluster(cluster)
        joint.type = classifyTopology(joint)
        joints.add(joint)

    return removeInvalidAndDuplicates(joints)

14. Edge cases

Very short elements

Elements shorter than the endpoint tolerance can become ambiguous. Consider rejecting them or applying special handling.

Near-parallel elements

Numerical errors can create unstable intersection points. Apply angular and positional tolerances.

Duplicate geometry

Two identical elements should not create duplicate physical joints.

Nearly coincident endpoints

Cluster nearby candidates before final topology classification.

15. Implementation roadmap

Phase 1 — Core straight geometry

  1. Normalize line/segment representation.
  2. Implement robust line intersection.
  3. Implement endpoint proximity.
  4. Implement L, T, collinear and X classification.
  5. Add unit tests for tolerance boundaries.

Phase 2 — Topology

  1. Cluster candidate intersections.
  2. Merge participating element IDs.
  3. Implement Y-junctions.
  4. Implement multi-way joints.
  5. Handle duplicate candidates.

Phase 3 — Advanced geometry

  1. Add overlap detection.
  2. Add line/curve intersections.
  3. Add curve/curve intersections.
  4. Add tangent classification.
  5. Add confidence and diagnostics.
Recommended implementation boundary: Keep detectJoints() responsible for geometric/topological relationships. Domain-specific meanings such as hinge, weld, screw, bracket or adhesive attachment should preferably be interpreted by a higher-level component.
